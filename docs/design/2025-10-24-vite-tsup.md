# 技术方案：Vite + tsup 现代化改造

日期：2025-10-24

## 背景与目标

fabric-photo 是基于 fabric.js 1.7.3 的纯前端图片编辑器库。当时工具链陈旧且部分已损坏：

- 库构建用 rollup 2 + `@rollup/plugin-typescript`，配置里残留大量无用 babel 依赖
- 本地 demo 用 webpack-dev-server，页面依赖 bootcss CDN 的 jQuery/lodash（CDN 已不稳定）
- GitHub Pages 示例站由 `website/` 内的 dumi 2 构建，docs 内嵌的 demo 与 `website/src/demo` 双份维护，且引用了不存在的样式路径
- CI 使用过老的 actions（checkout@master、setup-node@v1）、Node 10，且用 npm 而仓库统一 pnpm

确认的四项目标：

1. **Vite demo 统一部署**：废弃 dumi，本地开发与 GitHub Pages 使用同一份 Vite demo
2. **现代化 CI**：pnpm + Node 20 + 最新 actions，保持部署到 `gh-pages` 分支
3. **现代 exports map**：tsup 产物 CJS + ESM + d.ts
4. **原生 JS 替代 jQuery**：删除 bootcss CDN script 标签

## 总体方案

demo 源码从 `website/src/demo` 提升为根目录 `demo/`，删除整个 `website/`。Vite root 即 `demo/`，本地 dev 与 Pages 部署同源。

已否决：demo 原地留在 `website/src/demo`（目录名失去意义）；保留 dumi 文档站（两份 demo 代码）。

## 详细设计

### 1. 库构建：rollup → tsup

- `tsup.config.ts`：entry `src/index.ts`，format `['cjs', 'esm']`，`dts` / `sourcemap` / `clean`
- fabric 1.7.3 保持 bundle 进产物（不 external；它是 CJS/UMD 老包，external 会破坏浏览器直连）
- 产物：`dist/index.js`（CJS）、`dist/index.mjs`（ESM）、`dist/index.d.ts`
- `package.json` 增加 `exports` map；`build` 改为 `tsup`；`typecheck` 保持 `tsc --noEmit`
- 删除 `rollup.config.js`、`babel.config.js` 及全部 rollup / babel / webpack 相关 devDependencies
- 保留 eslint / prettier / husky / lint-staged / commitlint 等工程化依赖
- 卸载 `lerna`（当时是单包）

产物不支持在 Node 中直接 `require`（fabric 1.7.3 在模块加载期触碰 DOM，旧 rollup 产物同样如此，非回归）。功能验证走浏览器冒烟。

### 2. Demo：webpack-dev-server → Vite

- `website/src/demo/` → `demo/src/`；样式与 `public/images/` 一并迁移
- `html/index.html` → `demo/index.html`：去掉 jQuery/lodash CDN，入口改为 `<script type="module" src="/src/index.tsx">`
- 根目录 `vite.config.ts`：`root: 'demo'`，`@vitejs/plugin-react` 且 `jsxRuntime: 'classic'`（兼容 React 16 + `ReactDOM.render`）
- dev server 端口 `9876`；build `outDir: '../dist-demo'`；Pages 的 `base` 为 `/fabric-photo/`
- `$()` 三处改为原生 DOM API
- 删除 `webpack.config.js`、`html/`、`public/`（旧 webpack 产物）

### 3. GitHub Actions

`.github/workflows/github-pages.yml` 保持同名与触发条件，构建步骤改为：

1. `actions/checkout@v4`
2. `pnpm/action-setup@v4`
3. `actions/setup-node@v4`（Node 20，`cache: pnpm`）
4. `pnpm install --frozen-lockfile`
5. `pnpm build:demo`
6. `JamesIves/github-pages-deploy-action@v4` 部署 `dist-demo` 到 `gh-pages`

部署 token 使用 `secrets.GITHUB_TOKEN`，job 授予 `permissions: contents: write`。线上 URL `https://ximing.github.io/fabric-photo/` 不变。

### 4. 清理与文档

- 删除整个 `website/` 及 `install:website` / `build:website` scripts
- 更新 `readme.md` 开发命令（`pnpm dev` / `pnpm build` / `pnpm build:demo`）

## 明确不做

- 不升级 fabric.js（锁定 1.7.3）
- 不升级 React 16 → 18
- 不迁移 ESLint 配置
- 不改动 `src/` 库源码逻辑、`scripts/ralph/` 工作流
- 不发布 npm 新版本
